# SignedChat frontend

React 19 + Vite + TypeScript, Tailwind CSS v4, shadcn/ui, and Kokonut UI. The fixed dark theme uses obsidian `#09090B`. Existing signed-mail and key-vault flows are implemented as React components.

## Local development

Requires Node.js 22.12+ (Node 24 recommended) and the existing Java 21+ backend.

```powershell
# Terminal 1, from backend/
.\mvnw.cmd spring-boot:run

# Terminal 2, from frontend/
npm.cmd ci
npm.cmd run dev
```

Open http://127.0.0.1:5173. The Vite dev server forwards `/api` to http://127.0.0.1:8080. Using `npm.cmd` avoids Windows PowerShell's npm.ps1 execution-policy issue.

The convenience launcher supports the previous port/backend arguments:

```powershell
.\start.cmd 5174 http://127.0.0.1:8080
```

Alternatively set `BACKEND_URL` in your shell or a local `.env.local`. This configures Vite's server-side proxy, not browser credentials. Production uses same-origin `/api` calls.

## Build and check

```powershell
npm.cmd run build
npm.cmd run preview
npm.cmd test
npm.cmd run lint
npm.cmd run format
```

The strict TypeScript/Vite build writes `dist/`. Preview serves it on http://127.0.0.1:4173 with the API proxy. `npm test` runs React Testing Library/Vitest flow and ESM-import checks, then the original `node --test math.test.cjs` cryptographic vectors. Test fixtures use synthetic keys, not real user secrets.

The root Dockerfile builds the frontend in Node, copies `dist/` into Spring Boot's static resources, then packages Java. The running Render image needs only Java. For manual Spring hosting, copy the contents of `frontend/dist/`, not frontend source files, into `backend/src/main/resources/static/` before packaging.

## Structure

- `src/App.tsx`: username lookup, create-user flow, Key Vault, memory-only identity, logout.
- `src/components/mail-workspace.tsx`: all-sender inbox, reading pane, username/public-key search, full-key compose, exact-content send.
- `src/components/simulation.tsx`: two selectable demo identities.
- `src/components/math-lab.tsx`: disposable-key Ed25519 math, all nine stages and expandable scalar rounds.
- `src/components/ui/`: shadcn primitives generated by the official CLI.
- `src/components/kokonutui/particle-button.tsx`: official Kokonut component, used for continuing from the vault. Upstream MIT attribution is retained.
- `src/lib/api.js`, `src/lib/math.js`: importable ESM copies of the existing helpers, with adjacent TypeScript declarations.
- `src/lib/use-task.ts`: guards against stale responses after logout/unmount.
- `src/index.css`: Tailwind v4, shadcn tokens, local Geist font, obsidian theme.
- `src/styles/workspace.css`: retained responsive workspace layout.
- `components.json`: shadcn aliases and `@kokonutui` registry.
- `legacy/`: the archived vanilla index, styles, app, math UI, tests, launcher, and helper copies. It is reference code and excluded from production Docker input.
- Root `api.js`, `math.js`, and `math.test.cjs` remain accessible and unchanged.

## Direct imports

```ts
import { createApi } from '@/lib/api.js'
import { payload, traceSignature, hex, fromHex } from '@/lib/math.js'

const api = createApi()
const users = await api.listUsers()
```

REST request/response schemas and the signing payload remain unchanged. The ESM copies export functions directly; React does not depend on `window.SignedChat` or `window.SignedChatMath`.

## UI registries

shadcn was initialized with the official CLI's Radix Nova preset. Tailwind v4 uses its Vite plugin; no v3 tailwind.config file is needed. The `@/` alias points to `src/`.

`components.json` contains:

```json
{
  "registries": {
    "@kokonutui": "https://kokonutui.com/r/{name}.json"
  }
}
```

Install further components with `npx.cmd shadcn add button` or `npx.cmd shadcn add @kokonutui/particle-button`. Registry URLs are plain URLs, not Markdown links. Vendored UI files retain their upstream exports/ref patterns; targeted lint overrides apply only to those generated components.

## Behavior and limits

Home checks a username. A 404 opens Create User; connection errors remain errors. Existing or newly created users enter the copyable Key Vault, then Mail Workspace. The vault's private key state clears on Continue or Logout. Workspace identity is public-only and memory-only, with no localStorage/sessionStorage persistence. Logout unmounts all inbox, draft, simulation, and math state; async guards ignore late results. Copied clipboard text remains under the user's control.

The identity screens use shadcn Cards, Inputs, Buttons, Badges, and Alerts over Kokonut's `background-paths`. Confirm creation using `slide-to-confirm` (drag the arrow, or focus it and press Enter/Space); failed requests reset the slider for retry. The vault displays `@username`, the X.509 public key, and a PKCS#8 private key behind controlled `spoiler-text`. Private-key text is inserted into the page only after reveal; copying is disabled until then. Hide, leave the vault, or log out to reset the reveal state. This visual concealment does not change backend access permissions.

This is demo identity selection, not authenticated login. The backend deliberately exposes demo private keys through username lookup; use classroom keys only. Server-held keys and messages are in memory and reset on restart.

Inbox includes every received sender, with backend-acceptance badges and expandable signatures. The current API has no timestamps, so the reading pane says **Not provided by server**. If a valid server `timestamp` is provided later, it is displayed rather than fabricated.

User/public-key search filters fetched public records; it does not authenticate fingerprints. Messages remain plaintext, replay defense is absent, and the Attack Lab is a later implementation. The math lab uses disposable keys and native WebCrypto cross-checks; real chat signing stays in Java JCA.
